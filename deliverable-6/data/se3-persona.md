# SE3 persona: the new producer

Written before any step was judged. Source: `deliverable-3/proxy-scenario.md` (branch `deliverable-3-instruments`), plus the task brief.

**Who.** The producer on a small volunteer Unity team (SS3D). Just joined; has not worked on any of the weeks and does not know the people. Plans and tracks the team's work. Does not write code.

**What they know.** Production words: milestone, build, stand-up, testers, "what changed this week". Has used a tracker or a shared doc. Knows the team keeps its work "in a repository" but thinks of it as the GitHub web page, not a folder on disk. Does not know git commands, Unity's menus, or Unity terms (prefab, component, Canvas Renderer, placed-prefab overrides). Understands "scene" as a level and "prefab" as a reusable object only because the scenario defines them.

**Set-up.** Has the team's Unity project installed only to run tools. Can open it from Unity Hub and wait for it to load; has not explored the Editor's menus.

**Goal each week.** On Monday morning before stand-up: understand what the team did last week, know what to ask testers to check in the next build, and give a short update to the team and the people the team reports to.

**The tension.** The proxy scenario says the producer "does not open the Unity project", and the page is meant to arrive as a one-page summary that is "turned automatically" from the version history. ChangeLens, however, only makes that page inside the Unity Editor (Window > ChangeLens Producer Page). So for CW1, CW3, CW4 and CW5 this persona has to do what the scenario says a producer does not do: open Unity, find a developer-tool menu, and point it at a git clone. The walkthrough judges the window as this persona would meet it, so problems that come from the tool living in Unity are counted, not excused.
